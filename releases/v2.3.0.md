# v2.3.0 — Orchestrated Response

Phase 3 Commit 3 connects the repository's independent response actions into a controlled AWS Step Functions reference workflow for EC2 incidents.

## Highlights

- Adds `triage`, `containment`, and `rollback` orchestration modes.
- Preserves EBS evidence before live network containment.
- Requires explicit human callback approval before live EC2 isolation and live security-group restoration.
- Uses a dedicated KMS-encrypted SNS approval topic so task tokens are isolated from routine incident notifications.
- Suppresses duplicate requests with a DynamoDB conditional `event_id` record.
- Adds bounded retries, catches, approval timeouts, structured outcomes, and explicit partial-failure handling.
- Keeps automatic finding ingestion out of scope until Phase 3 Commit 5.

## Deployable components

Terraform now provisions the existing action Lambdas plus:

- EC2 incident-response Step Functions Standard Workflow;
- Step Functions execution role;
- approval SNS topic;
- DynamoDB execution-correlation table;
- Step Functions CloudWatch Logs group; and
- standalone approver callback IAM policy.

## Safety model

The reference workflow defaults to dry-run. A live containment execution may create EBS snapshots before the approval gate, but it will not isolate EC2 networking until an authorized callback returns `APPROVE`. Live rollback first validates the captured manifest and computes a dry-run restoration plan, then waits for separate approval.

Task tokens are sensitive and must be handled as authorization material. The approver policy is created for review but is not automatically attached to a human identity.
