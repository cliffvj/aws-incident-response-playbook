# v3.1.0 — EC2 Compromise & Isolation Lab

Phase 4 begins with a scenario-specific, deployable EC2 incident-response exercise built on top of the `v3.0.0` automated response platform.

## Highlights

- Deployable Amazon Linux 2023 EC2 target in a dedicated practice VPC.
- No inbound SSH/RDP rules; Systems Manager is the management and evidence plane.
- IMDSv2 required and root EBS encryption enabled.
- Harmless suspicious-activity marker created through SSM Run Command.
- Deterministic simulated EventBridge finding using the existing `aws-ir.lab` contract.
- Detection routed through the Phase 3 normalizer with conservative notify-only behavior.
- Read-only SSM evidence collection before quarantine.
- EBS snapshot preservation, approved Step Functions containment, and incident-specific security-group quarantine.
- Read-only target and isolation verification helpers.
- Recovery through checksummed rollback data and a separate approval boundary.
- Architecture, expected-results checklist, troubleshooting, interview review, unit tests, safety validation, and CI integration.

## Safety model

The exercise uses no malware, vulnerability exploitation, malicious persistence, credential theft, destructive payloads, or data exfiltration. The simulation is explicitly labeled and scoped to the dedicated lab.

Live containment is not automatically initiated by the detection layer. The responder explicitly starts the Step Functions workflow, and network isolation still requires the existing human approval callback.
