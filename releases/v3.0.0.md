# v3.0.0 — Automated Response Platform

Phase 3 is complete. This release adds the authorized end-to-end capstone that validates the response platform built across `v2.1.0` through `v2.6.0`.

## Highlights

- Benign EC2 suspicious-activity target deployed with standalone Terraform.
- No inbound security-group rules, encrypted root EBS, and IMDSv2-required metadata settings.
- Lab-only `aws-ir.lab` EventBridge finding injection into the existing detection normalizer.
- Conservative detection routing: notification or read-only dry-run triage, never automatic live containment.
- Read-only Systems Manager evidence collection before isolation.
- Explicit live Step Functions containment request with EBS evidence preservation and human callback approval.
- Ruleless quarantine security-group verification.
- Rollback input extracted from the completed containment execution's checksummed manifest.
- Separate human approval for restoration.
- Complete validation, troubleshooting, cost/retention, teardown, limitations, and portfolio checklist.

## Safety model

The lab intentionally does not use malware, exploit code, reverse shells, persistence, credential harvesting, or data exfiltration. A harmless marker file represents suspicious activity. Live response remains an explicitly authorized operator action.

## Validate before apply

Validate both Terraform roots and run `python3 automation/scripts/validate_capstone_lab.py`. Always review `terraform plan` and verify the AWS account/Region before apply.
